[STRUCTURE — OPTIONAL GUIDANCE]

Write the shortest direct chain that maps the prompt to atoms. Most prompts
need only 1-3 atom calls. Use freeform, meaningful variable names
(e.g. `vehicles`, `peds_at_crossing`, `moving_buses`). Conventionally bind
the final result to `referred` so the final call reads
`output_scenario(referred, description, log_dir, output_dir)`.

Simple example shapes:

```python
vehicles = get_objects_of_category(log_dir, category='VEHICLE')
referred = changing_lanes(vehicles, log_dir)
output_scenario(referred, description, log_dir, output_dir)
```

```python
ego  = get_objects_of_category(log_dir, category='EGO_VEHICLE')
peds = get_objects_of_category(log_dir, category='PEDESTRIAN')
peds_at_crossing = at_pedestrian_crossing(peds, log_dir)
referred = has_objects_in_relative_direction(ego, peds_at_crossing, log_dir,
                                              direction='forward',
                                              within_distance=30, lateral_thresh=5)
output_scenario(referred, description, log_dir, output_dir)
```

Use a longer cascade-style chain ONLY when the prompt genuinely requires
multiple distinct filters; do not pad simple prompts.

[RULES]

- Do NOT emit `# L1 Context` / `# L2 Actor` / `# L3 Behavior` / `# L4 Relation`
  comments, nor blank-line separators inserted to mimic the layer structure.
  The Selector's layer tags are for YOUR reasoning; the output should be
  compact contiguous Python. At most ONE comment line is allowed, and only
  when it captures a non-obvious WHY
  (e.g. `# 150m AND NOT 30m -> 30-150m range`).
- Variable names are NOT fixed. Use whichever names make the chain readable.
  The final atom-binding variable should be named `referred` for clarity at
  the output_scenario call.
- Atom application order is NOT fixed. Apply filters in the sequence that
  reads naturally for the description.
- L2 actor selection: if the prompt names a category, start with
  `get_objects_of_category(log_dir, category='X')` (super-categories 'VEHICLE'
  and 'ANY' are supported) or use `is_category(candidate_set, log_dir,
  category='X')` to narrow a previously filtered set. For cluster mappings
  (truck → TRUCK|BOX_TRUCK|TRUCK_CAB, motorcycle → MOTORCYCLE|MOTORCYCLIST,
  delivery truck → TRUCK|BOX_TRUCK, official signaler → OFFICIAL_SIGNALER|PEDESTRIAN,
  animal → ANIMAL|DOG) use `scenario_or([...])`.
  Single subtype only when the prompt names it (BOX_TRUCK, SCHOOL_BUS).
- `get_visual_actor` / `get_visual_behavior` (VLM crop filters): the candidate
  set you pass in MUST be a BROAD gather — NEVER prepend `is_category` to narrow
  it to the "obvious" class. The tracker mislabels subtypes, so narrowing can
  drop the target before the VLM ever sees it.
    * `get_visual_actor` (named subtype with NO AV2 category — police car,
      ambulance, fire truck, forklift, cement mixer, food truck, construction
      worker, child): gather the broad bucket, THEN filter. Vehicle-type ->
      `cands = scenario_or([get_objects_of_category(log_dir, category='VEHICLE'),
      get_objects_of_category(log_dir, category='WHEELED_DEVICE')])` (WHEELED_DEVICE
      adds forklift/UTV/excavator, which 'VEHICLE' misses); person-type or unsure
      -> `cands = get_objects_of_category(log_dir, category='ANY')`. Then
      `referred = get_visual_actor(cands, log_dir, '<short phrase>')`.
    * `get_visual_behavior` (visible behavior/appearance/state confirmable from
      ONE crop — person on a ladder, vehicle carrying a bicycle, covered by a
      tarp): gather the BASE actor category first (e.g.
      `get_objects_of_category(log_dir, category='PEDESTRIAN')` or `'VEHICLE'`),
      THEN `get_visual_behavior(actors, log_dir, '<short phrase>')`.
- The final call MUST be `output_scenario(referred, description, log_dir, output_dir)`.
- Variables `log_dir`, `description`, `output_dir` are injected by the runtime
  — do NOT define them.
- `is_category` signature: `is_category(track_candidates, log_dir, category='X')`
  — first arg is candidate set; category is a SINGLE string, NO `|` separator.
- Set explicit numeric kwargs ONLY when the description names a specific scale
  ("within 5 meters", "directly", "right next to", "very close"). Otherwise
  use defaults (no lateral_thresh, within_distance 30-50) — looser matching
  empirically yields better GT recall.
- AVOID action atoms (braking / braking_hard / reversing / between_two_objects /
  following / cut_in_front_of) unless the description contains the exact
  trigger word. For paraphrases use position + category chain only.
- For "X is REFERRED by Y" wordings, use `reverse_relationship(func)` to swap
  subject/related at the relational atom call.
- For "X near/ahead/behind ego" queries when uncertain, prefer the ego-keyed
  form over a narrow chain that may empty.
- If your chain looks like it could empty out, FALLBACK to a broader output
  (e.g. just the category set without the narrow filter).
  An overly-broad output beats an empty narrow one for HOTA-T scoring.
- Do NOT call any function not present in INVARIANT or SELECTED ATOMIC FUNCTIONS.
- Do NOT add commentary outside the python block.
