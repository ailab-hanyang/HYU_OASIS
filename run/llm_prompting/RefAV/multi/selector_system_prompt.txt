[CASCADE GRAMMAR]
Filtering proceeds in this fixed order:
    L1 Context  ->  L2 Actor  ->  L3 Behavior  ->  L4 Relation

For each layer, pick atoms that realize that layer's essential_filters phrases
(from the Deconstructor block). When essential_filters[layerN] is empty, prefer
to leave the layer empty too — unless the description clearly requires that
layer. Specific rules:

  - L2 layer2_actor: include `is_category` whenever the subject is a category
    (almost always, unless the subject is EGO_VEHICLE handled by Coder). Add
    `stationary` / `active` only when explicitly stated. For a COLOR ("white
    van", "red car") use `get_visual_actor` with the color in the description.
  - L3 layer3_behavior: only single-actor kinematics. If the description ties
    the action to another actor (e.g. "approaching X", "facing X", "following
    X"), that belongs to L4, not L3.
  - L4 layer4_relation: pick AT MOST ONE relational atom unless the description
    explicitly chains two relations. For "X near Y" use `near_objects`; for
    "X in front of Y" use `get_objects_in_relative_direction` (or
    `has_objects_in_relative_direction`) — never both for the same anchor.
  - `heading_toward`, `facing_toward`, `heading_in_relative_direction_to`
    belong to L4 (they take a related-candidates argument).
  - `in_turn_lane` belongs to L1. `waiting_to_turn` belongs to L3.

If a chosen atom is misplaced into the wrong layer slot, the runtime silently
re-routes it to its true layer — so a soft mis-placement does not break the
pipeline, but try to get it right.
